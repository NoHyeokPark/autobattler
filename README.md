# 덱빌딩 오토배틀러 프로토타입 v0.2

설계 문서 v0.1 기반의 프로토타입. 핵심 루프(상점 → 노드 선택 → 매칭 → 전투 → 보상)와 PvP 기록 매칭, 밸런스 시뮬레이터, 웹 버전과 기획자용 에디터까지 포함한다.

## v0.2 변경 사항 (규칙 버전 2 — v1 저장·기록과는 호환되지 않음)

| 항목 | 내용 |
| --- | --- |
| 장신구 중첩 | 같은 장신구가 상점·보상에 다시 나오고, 가진 개수만큼 효과가 무한히 중첩된다 (상점 레벨·수입 보너스 포함). 배낭은 `x2`처럼 묶어서 표시. 한 번의 진열·선택지 안에서만 겹치지 않는다 |
| 몬스터 성장 | Lv2가 되면 (그 몬스터 전용 성장 + 공용 성장) 중 3개를 제시하고 하나를 고른다. Lv3은 새로 고르지 않고 합성에 쓴 Lv2 3장의 성장을 모두 가진다 (반복 가능 성장은 중첩, 반복 불가 성장이 겹치면 하나만). 고르는 레벨은 `balance.unit.growthChoiceLevels` |
| 전투 밖 효과 | 새 효과 3종: **영구 강화**(공격력·체력·주문력·행동 간격·추가발동, 이번 전투에 바로 적용 + 유닛에 남음), **골드 획득**, **무작위 장신구 획득**(등급 지정). 플레이어 쪽만 전투 후 런에 반영되고 **승패와 무관** (연패하며 스택 쌓기 가능). 골드·장신구는 전투당 상한(`balance.battleGains`, 기본 8골드·2개)으로 추가발동 폭주를 막는다. 상대(기록)의 영구 강화는 기록 당시 값으로 남아 있어 PvP에서도 쌓인 유닛을 만난다 |
| 봇 전략 | 성장형·경제형 추가 (시드 봇은 전투가 없어 기존 3전략만). 모든 봇은 남은 목숨이 2 이하면 모아 둔 골드를 리롤에 몰아 쓰는 "올인"을 한다. 이게 없을 때 이자형은 4패 상태에서도 평균 73골드를 들고 14%만 쓰고 탈락했다 (올인 후 평균 승 2.2~2.7 → 3.5~3.7) |
| 성장형·경제형 콘텐츠 | 애벌레·수련생·고대 거북·현자(영구 강화), 행상 고블린·금광 드워프(골드), 보물 사냥꾼·장신구 "보물 지도 조각"(장신구), 공용 성장 "자라나는 힘", 기사 성장 "백전노장"(리더도 쌓임) |
| 영구 강화 병합 | 같은 유닛에 쌓이는 영구 강화는 합산, 합성 때는 **합산하지 않고 계열별 최고값**만 남는다 (행동 간격은 가장 많이 줄인 값). Lv1에 강화를 모아 한 번에 키우는 것을 막기 위함. 성장은 합성 때 모두 합쳐진다 |
| 성장 선택지 확장 | 리더·몬스터 공통: 능력치(고정·%·주문력), **새 능력 추가**, **기존 능력 제거**(둘을 함께 쓰면 교체), **태그 추가·제거** |
| 엘리트 보상 | "엘리트 보너스: 확률표 앞당김" 수치 삭제. 대신 확률표를 앞당기는 장신구 추가(탐험가의 지도 +2, 기존 망원경 +1, 중첩 가능) |
| 상점 | 6칸 |
| 일차별 체력 | 양측 최대 체력에 일차별 배율 적용 (`balance.scaling.hpPctByDay`, 100% → 14일차 300%). `npm run sim -- days`로 맞춰서 전투 평균 길이가 전 일차 19~23초로 유지되고, 14일차 3초 내 종료가 11.6% → 0%가 됨 |
| 능력 대상 | 대상 = **진영(아군/상대) + 범위(전체 / 방향 지정 / 같은 행 / 같은 열)**. 방향은 기준 칸 주변 8방향+기준 칸의 아무 조합. 상대 쪽 기준 칸은 같은 번호의 칸(대칭 위치). 예) "아래 아군 공격력 +40%", "대칭 위치의 위·오른쪽 상대 공격력 -20%" |
| 주문력 | 유닛 능력치 `주문력` 추가 (레벨 배율·성장으로 함께 오름). 독·재생·강화 중첩 = 주문력 x% (반올림). 피해·회복·실드에도 주문력 %를 섞을 수 있다. 장신구처럼 유닛이 없는 효과는 고정값 |

예전 형식 모드 파일(대상 `scope`, 상태 `stacks`)은 불러올 때 새 형식으로 자동 변환된다.

## 실행

Node.js 22.18 이상(TypeScript를 빌드 없이 바로 실행)이 필요하다.

```bash
npm install
```

```bash
npm run play
```

| 명령 | 설명 |
| --- | --- |
| `npm run web` | **웹 버전** (http://localhost:5173). 게임 + 기획자용 에디터 |
| `npm run web:build` | 웹 정적 빌드 (`dist/`) |
| `npm run play` | 터미널 버전. 옵션: `-- --new`(저장 무시하고 새 런), `--seed 42`, `--speed 1\|3\|skip`, `--mod 파일.json` |
| `npm run sim -- league --runs 300 --write` | 봇 300판을 돌리고 그 기록을 PvP 상대 풀(`saves/records.json`)로 저장. **처음 한 번 돌려 두면 시드 봇 대신 기록과 매칭된다** |
| `npm run sim -- pairs --n 2000 --day 8` | 무작위 팀 대전 통계 |
| `npm run sim -- slots --n 30` | 칸 효과 비교 |
| `npm run sim -- days` | 일차별 전투 길이 (일차별 체력 배율 조정용) |
| `npm test` | 엔진·게임 규칙 테스트 |
| `npm run typecheck` | 타입 검사 |

Windows 콘솔에서 한글이 깨지면 `chcp 65001`을 먼저 실행한다. 터미널 버전의 저장 위치는 `saves/`(환경변수 `AB_SAVE_DIR`로 변경 가능), 웹 버전은 브라우저 localStorage.

## 웹 버전

**게임 탭**: 리더 선택 → 상점 단계(보드 3x3·벤치·상점·노드) → 전투 재생 → 분석 → 보상. 유닛은 클릭으로 선택한 뒤 다른 칸을 누르거나 끌어다 놓아 옮기고, 오른쪽 상자로 끌어다 놓으면 판매한다. 단계마다 자동 저장된다. 리더 선택 화면의 "봇 기록 생성"으로 PvP 기록 풀을 브라우저 안에서 만든다.

**카드**: 일러스트가 없으면 등급색 프레임 안에 흰 배경 + 검은 글씨. 일러스트는 프로젝트의 `art/` 폴더에 파일로 두며, 레벨과 **외형 변화 성장**(이브이 진화처럼 성격이 크게 바뀌는 성장)마다 다른 이미지를 쓸 수 있다. 파일 이름 규칙은 [art/README.md](art/README.md). 에디터의 "일러스트" 칸에서 올리면 최대 512px webp로 줄여서 저장한다. Lv3 합성 때 재료들의 외형이 다르면 어느 외형으로 진화할지 고르는 창이 뜬다. 설명(`desc`)을 비우면 능력 데이터에서 설명을 자동으로 만든다.

**에디터 탭** (기획자·모드 도구):

| 탭 | 내용 |
| --- | --- |
| 몬스터 / 리더 / 장신구 | 카드 목록 + 폼 + 실시간 카드 미리보기(Lv1~3). 능력은 "트리거(전투 시작/행동 시/N초) → 효과" 편집기로 만든다. 대상은 진영 + 3x3 방향 선택판. 몬스터·리더는 성장 선택지 편집(능력치, 새 능력, 기존 능력 제거 체크, 태그 추가·제거). 성장의 "외형 변화" 표시. 레벨·외형별 일러스트 칸(파일 이름·대체 이미지 표시, 업로드·삭제). 새로 만들기·복제·삭제, JSON 직접 편집 |
| 공용 성장 | 모든 몬스터가 레벨업 때 공유하는 성장 선택지 |
| 수치 | `balance.ts`의 모든 수치 (상점 확률표는 표로 편집) |
| 테스트 | 두 팀을 직접 짜서 전투 재생·분석 / 봇 팀 대전으로 카드 승률·전투 길이 통계 |
| 모드 | 모드 이름, 태그 추가·삭제, JSON 내보내기·가져오기, 기본값 초기화 |

편집은 초안에만 반영되고 **"변경 사항 적용"** 을 눌러야 게임에 들어간다. 오류(중복 id, 정수가 아닌 수치, 일반 몬스터 없음 등)가 있으면 적용되지 않는다. 내보낸 JSON은 터미널에서도 쓸 수 있다: `npm run sim -- pairs --mod 파일.json`.

### 상점 단계 명령어

```
buy N        상점 N번 구매 (같은 몬스터 3장이면 자동 합성)
sell X       판매. X = 보드 1~9 / 벤치 b1~b6
mv X Y       이동·교체. 예) mv b1 5
r / lock     리롤 / 상점 잠금
node N       노드 선택
i X          정보. X = 1~9, b1~b6, s1~s5
t / slots    장신구 목록 / 칸 효과표
go           준비 완료 → 매칭 → 전투
stop         (연장 중) 여기서 멈추기
```

## 구조

```
src/                  게임 로직 (터미널·웹 공용, 화면을 모름)
  config/balance.ts   모든 수치(확률표, 가격, 칸 효과, 서든데스, 안전 한도…). 코드와 분리
  data/               몬스터 28종(전용 성장 포함), 리더 3명, 장신구 19종, 공용 몬스터 성장 — 트리거→효과 데이터
    growth.ts         성장 적용 계산 (엔진·카드 공용) / targets.ts  대상 지정 도우미·예전 형식 변환
    registry.ts       모드 적용 (데이터 객체를 제자리에서 교체)
    validate.ts       모드 검증 / describe.ts  자동 설명 생성
  core/               결정적 난수(mulberry32), 정수 연산(안전 한도 클램프, BigInt 폴백)
  battle/engine.ts    결정적 tick 전투 엔진. 이벤트 로그만 출력
  game/               런 상태 전이, 상점·합성, 노드, 매칭(폴백), 봇, 저장, 리더 기록
  ui/                 터미널 화면: 상점, 전투 재생(배속), 전투 분석
  sim/                밸런스 시뮬레이터 (pairs.ts·league.ts는 웹 에디터도 사용)
web/                  React 웹 프론트엔드
  components/         카드, 3x3 보드, 모달
  game/               게임 화면 (상점 단계, 전투 재생, 분석, 선택 창)
  editor/             에디터 (유닛·장신구·수치·테스트·모드)
test/                 node:test 테스트
```

- **시너지 3종을 하나의 구조로**: 모든 능력은 `트리거(battleStart / act / timer) → 효과[]`이고, 태그 버프는 `tag` 필터, 위치 효과는 `adjacent`·`mirror`·`sameRow` 필터로 표현한다. 새 시너지는 대부분 데이터만 추가하면 된다.
- **엔진**: 10 tick = 1초. 정렬 키는 (시스템 우선, 플레이어 우선, 슬롯 번호, 등록 순번). 같은 입력이면 항상 같은 결과이고, 기록 스냅샷(팀·배치·일차·환경·규칙 버전)만으로 전투가 재현된다.

## 미결정 항목에 넣어 둔 기본값

설계 문서의 미결정 항목은 아래처럼 임시로 정했다. 전부 `balance.ts` 또는 데이터에서 바꿀 수 있다.

| 항목 | 임시 결정 |
| --- | --- |
| 추가발동 | 추가 행동마다 "행동 시" 효과가 모두 다시 발동. 추가발동이 추가발동을 만들지는 않음. 행동당 처리 상한 200 |
| 기절 중 대기열 | 이미 남은 대기 시간이 0이 되어 대기열에 든 행동은 기절해도 실행됨 |
| 보스 노드 | 엘리트처럼 일차+1 기록, 환경은 3종 랜덤, 9승 이후 미등장. 12일차 보스가 10승째여도 보상은 지급(연장에서 쓰임) |
| 1행 x값 | 일차별 1,1,2,2,2,3,3,3,4,4,4,5,5,5 |
| 엘리트·보스 폴백 | 일차+1·같은 환경 → 일차+1·일반 환경 → 시드 봇(일차+1) |
| 경제 | 리롤 1G, 판매가 = 구매가 × 합성에 쓴 장수, 보상 대신 골드 4G(엘리트 보너스 4G, 보스 8G) |
| 서든데스 | 60초부터 매초 20 × 1.5ⁿ, 실드 무시 |
| 상태 효과 | 독: 매초 중첩만큼 피해(실드 무시), 재생: 매초 중첩만큼 회복, 강화: 공격 피해 +중첩. 감쇠 없음 |
| 상태 주기 효과 순서 | 상태를 건 진영 기준으로 플레이어 우선 |
| 상점 잠금 | 끌 때까지 유지 |
| 상점 레벨 장신구 | 후보 (a) 확률표 한 단계 앞당김 |
| 강제 종료 | 300초가 지나도 안 끝나면 남은 HP 비율 판정(동률은 플레이어) |

## 시뮬레이터 첫 결과 (v0.1 기준, seed 1 — v0.2에서 다시 측정 필요)

수치를 조정하기 전 상태의 관찰이다.

- **동률 우대**: 플레이어 측 승률 50.5%, 진영만 바꿨을 때 승패가 뒤집히는 매치 1.4%. 단, 회복·실드 유닛은 먼저 행동하면 가득 찬 HP에 회복을 낭비할 수 있어서 플레이어 우선이 항상 이득은 아니다.
- **전투 길이(8일차)**: 중앙값 일반 17초 / 체력 증가 19초 / 공격 증가 15초. 서든데스 발동 0.5~3.3%.
- **시작 즉시 종료**: 일반 환경 0.6%, 공격 증가 환경 1.3%가 t=0에 끝남 (3열 한방 유닛). 목표인 "사실상 0"보다 높다.
- **추가발동**: 팀 합계 10~19의 승률이 88.5%로 높다. 다른 빌드의 스케일링 조정이 필요하다.
- **골드 전략**: 이자형 봇의 평균 승수가 1.6으로 크게 낮다. 봇 휴리스틱이 단순한 탓도 있어서 결론을 내리기 전에 봇부터 다듬어야 한다.
- **엘리트·보스**: 엘리트 승률 약 26%, 보스 17~27%. 일차+1 상대가 꽤 강하다.
- **칸 효과**: 3·4·6칸이 어떤 몬스터에게도 최고 칸이 되지 않았다. 1·2·7·8칸에 쏠린다.
